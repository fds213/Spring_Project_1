# 이음(IEUM) 요구분석서

작성일: 2026-10-26 · 문서 상태: 검토용 초안

> **확인**은 사용자 답변으로 확인한 방향, **계획안**은 기존 계획서에서 가져온 미확정 요구사항이다. **미확정**은 추가 답변이 필요한 항목이다. 이 문서는 구현 완료 여부를 나타내지 않는다.

## 1. 서비스 목적과 구성

이음은 업체가 상품을 확인하고 모의 구매를 통해 전용 그룹웨어를 개설·사용하며, 이음 운영자가 업체와 이용 현황을 관리하는 **서비스 운영 플랫폼**이다. 그룹웨어에서는 사내 업무와 IT 지원 업무를 한곳에서 처리한다.

**상품 소개 → 모의 결제 → 업체·최초 관리자 생성 → 관리자 로그인 → 직원·부서 등록 → 그룹웨어 사용**을 구현한다. 하나의 애플리케이션·DB에서 업체 ID로 여러 업체를 구분한다. 주요 업무는 한 업체로 시연하고, 업체 간 접근 제한은 두 번째 업체의 최소 데이터로 확인한다. 실제 대금 청구와 업체별 서버·DB·도메인 자동 생성은 범위에서 제외한다.

| 구분 | 사용자 | 제공 내용 | 상태 |
|---|---|---|---|
| 상품 소개 웹사이트 | 이음 도입을 검토하는 방문자 | 서비스·기능·가격 안내, 비회원 문의 등록·답변 확인과 운영자 문의 관리 | 확인 |
| 모의 구매·업체 개설 | 서비스를 도입하려는 업체 담당자 | 업체·이용 인원·관리자 정보 입력, 금액 확인, 모의 결제 결과 저장과 전용 환경 개설 | 확인 |
| 업체 전용 그룹웨어 | 이음을 도입한 업체의 직원 | 전자결재, 근태·연차, IT 지원, 일정, 게시판, 채팅 등 | 확인 |
| 이음 운영자 화면 | 이음 서비스 운영자 | 업체 목록·이용 상태·모의 결제 내역·문의 관리 | 확인 |
| 시연 대상 | 주 시연 업체와 접근 제한 확인용 두 번째 업체 | 한 업체의 전체 업무 흐름 및 서로 다른 업체의 자료 접근 차단 | 확인 |

상품 홈페이지와 가격·문의 구성은 [다우오피스](https://daouoffice.com/)와 [하이웍스](https://main.hiworks.com/)를 참고한다. 이음의 안내 가격은 **단일 상품·1인 월 4,000원**으로 한다. 초기 비용·부가세·할인 조건은 미확정이다.

개발 인원은 프론트엔드 3명·백엔드 4명이다. AI를 적극 활용하며, 상세 담당 배정은 미확정이다.

## 2. 사용자와 권한

업체 관리자의 공통 지도 편집 권한과 사용자의 개인 지도 편집 권한은 확인됐다. 나머지 세부 역할 배정은 기존 계획안이다.

| 사용자 | 사용할 수 있는 기능 |
|---|---|
| 방문자·구매 담당자 | 서비스·기능·가격 확인, 모의 구매·업체 개설, 비회원 문의 등록과 문의번호·비밀번호 조회 |
| 이음 운영자 | 업체 목록·이용 상태·모의 결제 내역 확인, 홈페이지 문의 조회·답변. 업체 관리자와 구분하며 개별 업체 업무 자료 열람 범위는 별도 확인한다. |
| 직원 | 본인 근태·연차·결재·티켓·지급 자산 확인, 권한이 있는 일정·게시판·채팅 사용, 본인의 개인 지도 정보 편집 |
| 결재자 | 본인이 결재선에 지정된 문서 확인, 현재 본인 차례인 문서 승인·반려 |
| IT 담당자 | IT 티켓 처리, 자산 등록·지급·회수 및 이력 확인 |
| 인사 담당자 | 사원·근태·연차·휴일 관리 |
| 업체 관리자 | 개설된 본인 업체의 직원·부서 등록과 공통 지도 정보 편집. 기타 역할·지점 관리와 티켓 배정·재배정은 기존 계획안 |
| 부서장·업체 관리자 | 개인 지도 정보 소유자의 허가를 받은 경우 해당 정보를 조회한다. 직책만으로 자동 열람할 수 없다. |

- 한 직원에게 여러 역할을 부여할 수 있으며, 업체 역할의 효력은 소속 업체 안으로 제한한다.
- 관리자라도 관계없는 결재 원문과 개인 채팅을 자동으로 열람할 수 없다.
- 개인 지도 정보는 기본적으로 소유자 본인만 조회한다. 다른 직원·부서장·관리자의 최초 열람은 소유자가 직접 승인하며, 소유자는 언제든 허가를 해제할 수 있다. 묶음별 자동 승인을 켜면 이미 허가한 사람에게 이후 추가되는 마커를 자동 공유한다. 자동 승인을 끄면 이후 추가되는 마커부터 추가 승인을 받는다.
- 계정·부서·결재·근태·티켓·자산·지도·일정·게시판·채팅·파일·업무 알림을 업체별로 구분한다. 조회·등록·수정·삭제와 파일 접근·채팅 연결에서 업체와 자료별 권한을 함께 검사한다.
- 요청에 포함된 업체 ID만 신뢰하지 않고 로그인 사용자의 소속 업체를 확인한다. 다른 업체의 사원 지정·결재자 선택·채팅 초대·지도 공유도 차단한다.

### 3.2 업체 전용 그룹웨어

아래 기능 영역은 모두 초안에 포함한다. 지도 활용 방향과 채팅 구분은 사용자 답변을 반영했으며, 나머지 세부 규칙은 기존 계획안으로 검토한다.

| ID | 기능 | 요구사항 | 상태 |
|---|---|---|---|
| EMP-01 | 사원·조직 | 관리자가 사원을 등록하고 부서·직급·퇴사 상태를 관리한다. 직원은 조직도와 사원 검색을 사용한다. | 계획안 |
| AUTH-01 | 로그인·내 정보 | 소속 업체와 사용자를 식별해 로그인·로그아웃하고 본인 정보·비밀번호를 변경한다. 직원은 업체 관리자가 등록한다. 업체 식별 방법과 최초 관리자·직원의 로그인 ID 규칙은 추가 확인한다. | 업체 구분 확인 · 로그인 규칙 미확정 |
| APP-01 | 기안·결재함 | 휴가·장비 지급 신청서를 임시저장하거나 상신한다. 첨부파일과 최대 2명의 순차 결재선을 지정하고 문서 상태를 조회한다. | 계획안 |
| APP-02 | 승인·반려·재기안 | 현재 차례인 결재자만 승인·반려한다. 반려 사유를 저장하고 재기안은 기존 문서를 복사한 새 문서로 작성한다. | 계획안 |
| ATT-01 | 출퇴근 | 출근·퇴근 버튼으로 서버 시각을 기록한다. 본인의 월별 기록과 지각·조퇴 내역을 조회한다. | 계획안 |
| ATT-02 | 연차·휴일 | 인사 담당자가 초기 연차와 휴일을 등록한다. 직원은 잔여 연차를 조회하고 종일 연차를 신청한다. | 계획안 |
| TKT-01 | 장애·문의 접수 | 직원이 장애·문의를 등록하고 첨부파일·댓글을 남긴다. 본인 지급 장비를 선택하거나 자산 없이 문의한다. 목록 검색과 페이징을 제공한다. | 계획안 |
| TKT-02 | 배정·처리 | IT 담당자·관리자가 허용된 범위에서 담당자와 상태를 변경한다. 처리 결과와 변경 이력을 저장한다. 요청자는 해결 확인 또는 재요청한다. | 계획안 |
| AST-01 | 자산 관리 | 자산번호·종류·모델·상태·배치 지점을 관리하고 지급·회수·장애 이력을 조회한다. 이력이 있는 자산은 삭제 대신 사용 중지·폐기한다. | 계획안 |
| AST-02 | 장비 지급 | 승인된 장비 신청과 연결된 티켓에서 재고 장비를 지급한다. 지급 대상·상태·이력을 함께 기록한다. | 계획안 |
| MAP-01 | 지도 기본 기능 | 업체가 업무 목적에 맞게 주소 검색, 마커와 텍스트 추가 등 지도 기능을 사용한다. IT 지원 전용 용도로 한정하지 않는다. | 방향 확인 · 세부 미확정 |
| MAP-02 | 공통 지도 정보 | 업체 전체가 확인할 공통·중요 정보는 업체 관리자만 편집한다. 일반 직원은 해당 공통 정보를 조회한다. | 확인 |
| MAP-03 | 업무 자료 연결 | 지점·자산·티켓과 지도 정보를 연결할지 정한다. 기존 계획서는 해당 연결을 전제로 한다. | 미확정 |
| MAP-04 | 개인 지도 정보 | 사용자가 출장 장소 등 본인 업무에 필요한 마커·텍스트를 개별적으로 편집한다. 기본 조회 범위는 본인만이며 다른 사용자의 편집은 허용하지 않는다. | 확인 |
| MAP-05 | 지도 세부 동작 | 마커·텍스트의 저장 항목과 등록·수정·삭제 동작을 정한다. | 미확정 |
| MAP-06 | 직원 간 공유 | 다른 직원이 개인 지도 마커의 열람을 요청하면 소유자가 승인·거절한다. 소유자는 언제든 허가를 해제할 수 있다. | 확인 |
| MAP-07 | 허가 후 조회 | 부서장·관리자도 소유자의 허가를 받아야 조회할 수 있다. 거절·미승인·허가 해제 상태에서는 조회할 수 없다. | 확인 |
| MAP-08 | 지도 묶음 | 여러 마커를 묶어 관리하고 묶음 단위 열람 요청·승인·거절·허가 해제를 제공한다. 자동 승인이 꺼져 있으면 새 마커는 추가 승인 후 공유한다. | 확인 |

## 4. 주요 업무 흐름과 처리 규칙

시연은 상품 홈페이지의 서비스·가격 확인에서 시작해 모의 구매·업체 개설·최초 관리자 로그인·직원 등록·그룹웨어 사용으로 이어진다.

| 단계 | 동작·처리 규칙 |
|---|---|
| 구매 준비 | 업체·이용 인원·관리자 정보를 입력하고 서버가 계산한 월 금액을 확인한다. |
| 모의 결제 성공 | 주문·모의 결제 결과와 업체·관리자·기본 설정을 함께 반영한다. 중복 요청에도 업체·관리자는 한 번만 생성한다. |
| 모의 결제 실패 | 실패 결과를 남기며 업체와 관리자 계정은 생성하지 않는다. |
| 개설 도중 오류 | 업체·관리자·기본 설정의 불완전한 생성을 취소하고 성공 완료로 표시하지 않는다. 실패 기록·재시도 방식은 추가 확인한다. |
| 최초 사용 | 관리자가 해당 업체로 로그인하고 부서·직원을 등록한다. 직원은 해당 업체 그룹웨어를 사용한다. |
| 운영 확인 | 이음 운영자가 업체·이용 상태·모의 결제 내역을 확인한다. 두 업체 계정으로 자료 접근 제한을 검증한다. |

아래 그룹웨어 업무 처리 규칙은 기존 계획안이다.

| 업무 | 처리 순서 | 반드시 지킬 규칙 |
|---|---|---|
| 휴가 | 신청 → 순차 결재 → 최종 승인 → 연차 사용·휴가 일정·결과 알림 반영 | 상신·최종 승인 때 잔여 연차와 날짜 중복을 확인한다. 주말과 등록된 휴일은 사용 일수에서 제외한다. |
| 장비 지급 | 신청 → 최종 승인 → 지급 티켓 자동 생성 → 재고 장비 지급 → 요청자 수령 확인·종료 | 신청 수량은 1개다. 재고가 없으면 사유를 남기고 처리 중으로 유지한다. 같은 장비를 동시에 두 직원에게 지급하지 않는다. |

추가 확인된 흐름은 다음과 같다.

| 업무 | 처리 순서 | 반드시 지킬 규칙 |
|---|---|---|
| 홈페이지 문의 | 비회원 문의 등록 → DB 저장·문의번호 발급 → 운영자 답변 저장 → 문의번호·비밀번호로 답변 조회 | 업체 내부 IT 티켓과 구분한다. 다른 문의번호만 입력하거나 비밀번호가 다르면 문의·답변을 공개하지 않는다. |
| 개인 지도 열람 | 마커별 열람 요청 → 소유자 승인·거절 → 승인받은 사용자 조회 → 소유자 허가 해제 | 기본은 본인만 조회한다. 부서장·관리자도 같은 허가 절차를 따른다. 해제 후 추가 조회를 차단한다. |

지도 묶음의 자동 승인 규칙은 다음과 같다. 현재 초안의 합의 사항이며, 추후 요구 변경 시 수정한다.

| 상황 | 처리 |
|---|---|
| 처음 열람을 요청한 사람 | 자동 승인 설정과 관계없이 소유자가 직접 승인·거절한다. |
| 자동 승인을 켠 묶음에 새 마커 추가 | 이미 묶음 열람을 허가한 사람에게 새 마커를 자동 공유한다. |
| 자동 승인을 끈 뒤 새 마커 추가 | 이후 추가분부터 추가 승인 후 공유한다. 옵션을 끄는 동작만으로 기존 허가를 해제하지 않는다. |
| 특정 사람의 허가 해제 | 자동 승인 설정과 관계없이 해당 묶음의 추가 조회를 차단한다. |

예: ‘부산 출장’ 묶음을 팀장에게 허가하고 자동 승인을 켜면, 이후 추가한 출장 장소도 팀장이 조회할 수 있다. 새로 열람을 요청한 직원은 별도 승인을 받아야 한다.

- 결재 문서 상태는 임시저장·진행·완료·반려로 구분한다. 진행 문서의 본문과 결재선은 수정하지 않는다.
- 기안자 본인·퇴사자는 결재자로 지정하지 않으며, 같은 결재자를 중복 지정하지 않는다.
- 티켓 취소는 요청자가 직접 접수한 장애·문의의 접수 상태에서만 가능하다. 반려에는 사유를 기록한다.
- 티켓 재배정은 종료·취소·반려 전 상태에서 관리자만 수행한다. 승인된 장비 지급도 처리 불가 시 사유와 함께 반려할 수 있으며 완료된 결재는 유지한다.
- 기본 근무 시각은 09:00~18:00이다. 자동 퇴근은 하지 않으며, 사원·날짜당 근태 1건을 유지한다.
- 휴가 신청은 휴일 데이터가 준비된 기간으로 제한한다. 법정 연차 자동 산정은 하지 않는다.

### 우선 확인할 항목

1. 로그인 시 업체를 어떻게 구분하는가? 업체 코드·사용자 ID 입력 또는 업체별 접속 경로 중 선택하고, 같은 사번의 업체 간 중복 허용 여부를 정한다.
2. 업체 개설 때 자동 생성할 기본 설정과 관리자 입력 항목은 무엇인가? 이용 상태 종류와 운영자의 상태 변경·접근 중지 권한도 정한다.
3. 월 금액의 부가세·초기 비용, 이용 인원 제한 적용, 구매 후 인원 변경·갱신·취소·환불 시나리오의 포함 여부를 정한다.

### 이후 확인할 항목

- 시연 업체명, 관리자·직원 계정 준비와 접속 주소
- 개설 실패 기록·재시도 처리와 이음 운영자의 업체 내부 업무 자료 열람 범위
- 개인 마커 열람 요청 대상을 찾는 방법, 묶음 제거 마커의 허가 처리와 개별 허가의 관계
- 상품 홈페이지의 세부 메뉴, 가격의 초기 비용·부가세·할인 표시
- 업체명·로고 변경 등 업체 설정 범위
- 지도 정보와 자산·티켓 연결 여부
- 마커별 제목·설명의 저장과 등록·수정·삭제 동작, 공유·허가 유효기간
- 새 지도 묶음의 자동 승인 옵션 초기 상태. 자동 승인 적용 범위는 MAP-09의 확인된 규칙을 따른다.
- 기존 계획안의 결재 2단계, 휴가·장비 양식 2종, 권한 배정과 파일 제한 확정
- 대상 화면 크기·지원 브라우저·예상 사용자 수·응답시간·백업 기준

### 기존 계획서와 달라진 범위

기존의 ‘도입 완료된 한 업체 사용’ 가정에서 **모의 구매·여러 업체 개설·운영을 포함하는 서비스 운영 플랫폼**으로 변경했다. 개발 인원 구성은 프론트엔드 3명·백엔드 4명이다. 기존 계획서의 7명 기능별 분담과 일정은 이 변경을 반영해 별도로 재검토해야 하며, 이번 수정은 요구분석서에 적용했다.

## 7. 작성 근거
