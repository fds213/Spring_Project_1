## 산출물 올리는 법

1. 최신 `develop`에서 브랜치를 만든다. 이름은 AGENTS.md 'Git'대로 `feature/doc-<산출물>-<이니셜>`(예: `feature/doc-screen-list-dg`).
2. 번호 폴더에 제출본(PDF 등)을 넣는다. 원본은 고칠 수 있는 파일이 하나(docx·xlsx·pptx·drawio·md 등)이면 제출본(PDF 등)과 함께 넣고, 여러 파일 묶음(HTML·캡처 등)이면 제출본만 넣는다. 파일 이름은 `이음_<산출물 이름>.<확장자>`(예: `이음_화면목록서.pdf`, `이음_화면목록서.xlsx`)이고, 폴더 README에 정해 둔 이름이 있으면 그것을 따른다.
3. 폴더 이름에 공백과 마침표가 있으니 명령에서는 경로를 따옴표로 감싼다.

   ```bash
   git add "docs/6. 화면목록서/이음_화면목록서.pdf" "docs/6. 화면목록서/이음_화면목록서.xlsx"
   git commit -m "[docs] 화면목록서 추가"
   git push -u origin feature/doc-screen-list-dg
   ```

4. base를 `develop`으로 PR을 연다. `docs/`는 CODEOWNERS로 최준원에게 리뷰 요청이 자동으로 간다. 승인 1명과 `build` 검사 통과 뒤 작성자가 병합한다(문서만 바꾼 PR에서도 `build`가 돈다).

### 주의

- **크기:** 파일 하나는 50MB 아래로 둔다. GitHub는 50MB가 넘으면 경고하고 100MB가 넘으면 push를 거절한다. 시연 영상이 50MB 아래로 줄지 않으면 저장소 밖에 올리고 링크를 `9. 발표자료 및 시연영상/README.md`에 적는다. Git LFS는 쓰지 않는다(팀원마다 설치가 필요하고 무료 용량이 작다).
- **고칠 때:** 같은 이름으로 덮어쓴다(`_v2`·`_최종`을 붙이지 않는다. 이전 판은 git 기록에 남는다). 큰 파일은 고칠 때마다 저장소가 그만큼 커지니 거의 끝난 판을 올린다.
- **공개 저장소:** 실제 비밀번호·키(DB 비밀번호, 토스·카카오 키, 메일 앱 비밀번호)와 개인 정보를 빼고 올린다. 화면 캡처에 보이면 가린다. 한 번 올라간 파일은 지워도 기록에 남는다.
- **소스 코드:** 저장소 자체가 제출본이다. 마감 때 `main` 태그로 zip을 만드는 법은 [`10. 요약본 및 소스 코드/README.md`](10.%20요약본%20및%20소스%20코드/README.md)에 있다.
